# 인증 상태관리 구조

## ✅ Zustand 기반 인증 상태관리 흐름

### 1. **기본 구조 설계**

- 전역 인증 상태는 Zustand store로 관리 (isLoggedIn, user 정보 등)
- 브라우저 새로고침/재접속 시에도 상태 유지 (httpOnly 쿠키 기반)
- 클라이언트 JS에서 토큰 접근 불가능하도록 보안 유지

---

### 2. **인증 Store 구성 요소**

- **상태 (State)**

  - `isLoggedIn`: 로그인 여부 (boolean)
  - `user`: 사용자 기본 정보 (선택적, 필요시에만)
  - `isLoading`: 인증 상태 확인 중 여부 (boolean)

- **액션 (Actions)**
  - `login()`: 로그인 처리 및 상태 업데이트
  - `logout()`: 로그아웃 처리 및 상태 초기화
  - `checkAuth()`: 현재 인증 상태 확인 (쿠키 존재 여부)

---

### 3. **인증 확인 흐름**

- **SSR에서 초기 인증 확인**

  - `layout.tsx`에서 `cookies()`로 인증 쿠키 존재 여부 확인
  - 쿠키 존재 시 → 인증 상태 true로 초기화
  - Zustand store에 초기 인증 상태 설정

- **CSR에서 인증 상태 유지**
  - 페이지 전환 시 Zustand 상태 유지
  - 새로고침 시 Next.js middleware 또는 layout에서 쿠키 확인 → store 재초기화

---

### 4. **로그인 처리**

- 사용자가 로그인 시도 → `/api/auth/login` API 호출
- 로그인 성공 시:
  - Next 서버에서 httpOnly 쿠키 설정 (클라이언트로 전달)
  - Zustand store의 `login()` 액션 호출 → `isLoggedIn = true`
  - 필요 시 사용자 정보 store에 저장

---

### 5. **로그아웃 처리**

- 사용자가 로그아웃 요청 → `/api/auth/logout` API 호출
- 서버에서 쿠키 제거 처리
- Zustand store의 `logout()` 액션 호출 → 상태 초기화

---

### 6. **인증 필요 페이지 접근 제어**

- **클라이언트 측 보호**

  - 컴포넌트 내에서 Zustand store의 `isLoggedIn` 확인
  - 비로그인 시 로그인 페이지로 리다이렉트

- **서버 측 보호**
  - middleware.ts에서 쿠키 존재 여부 확인
  - 인증이 필요한 경로에 대한 접근 제어
  - 인증 없이 접근 시 로그인 페이지로 리다이렉트

---

## 📌 이점 및 고려사항

| 항목   | 설명                                                     |
| ------ | -------------------------------------------------------- |
| 보안성 | 토큰은 항상 httpOnly 쿠키로만 관리, JS 접근 불가         |
| 사용성 | 한 번 로그인 후 페이지 이동/새로고침 시에도 로그인 유지  |
| 성능   | 불필요한 API 요청 최소화 (쿠키 기반 확인)                |
| 확장성 | 필요 시 `/auth/me` API 추가로 상세 사용자 정보 로드 가능 |
